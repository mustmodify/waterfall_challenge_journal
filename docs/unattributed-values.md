# Unattributed values

Generated 2026-09-21, after migration 094.

Every value here is something the site displays today that no claim asserts.
They are not necessarily wrong -- most are probably jw's own, entered by hand
before the claims system existed -- but nothing records where they came from,
so nothing can corroborate, dispute or re-verify them.

This matters now because the facts table assumes every fact has at least one
claim behind it. Anything still listed here when the backfill runs gets no
fact row at all.

How these were checked: jw's typed messages in this session's transcript were
searched for each value, matching latitude and longitude together rather than
latitude alone, because a short latitude is a substring of a longer one and
matches spuriously. Four were traced and are recorded in migration 094. The
rest predate this session, so the transcript cannot settle them.

## What reviewing these looks like

Most of them sit close to claims we already hold, which is the tell that they
are a reading rather than a mistake. Turtleback Falls (334) displays
35.0922, -82.9663 while hikingwnc, ncwaterfalls, dwhike and OpenStreetMap all
cluster between 35.0923 and 35.0926 -- about 40 m away. Nobody disagrees about
which waterfall it is; there is simply a fifth number with no name on it.

So the per-value decision is usually one of two things: record it as a jw
claim because he took the reading, or drop it in favour of a source we already
hold and let the existing claims decide. Feature 366 shows a third and more
valuable outcome -- the number already belonged to a source we carry, and
finding that recovered a whole missing claim group.
